#### B. Strict Pydantic Schema & Medical Safety Rules
Defined in [`backend/app/schemas/prescription.py`](file:///c:/Users/gowth/OneDrive/Documents/MediMate/backend/app/schemas/prescription.py):
- **Zero Hallucination**: The LLM is strictly prohibited from inventing doses, formulations, or frequencies. Missing fields are tracked in `missing_fields`.
- **No Guesswork**: The system never infers administration times or routes without explicit evidence.
- **Conflict Flagging**: Conflicting instructions trigger `has_conflicting_instructions=True` and `needs_confirmation=True`.
- **Preserved Verbatim OCR Text**: Raw OCR text is kept separate from the LLM proposed structured model.
- **Safety Database Constraint**: PostgreSQL constraint (`check_unverified_cannot_be_active`) guarantees that medication schedules cannot be `'Active'` without `is_confirmed = TRUE`.

#### C. Secure Backend Endpoints
Implemented in [`backend/app/api/v1/endpoints/prescriptions.py`](file:///c:/Users/gowth/OneDrive/Documents/MediMate/backend/app/api/v1/endpoints/prescriptions.py):
| Method | Route | Description | Security & Safety |
|---|---|---|---|
| `POST` | `/api/v1/prescriptions/upload` | Upload & intake | Size limit (< 10MB), MIME check (PNG, JPEG, WebP, PDF), owner isolation |
| `GET` | `/api/v1/prescriptions` | User upload history | Filtered by `current_user.id` |
| `GET` | `/api/v1/prescriptions/{id}/status` | Extraction progress | Step tracking (`upload` → `ocr` → `extraction` → `ready_for_review`) |
| `GET` | `/api/v1/prescriptions/{id}/review` | Candidate extractions | Returns unverified proposal + verbatim OCR text |
| `PUT` | `/api/v1/prescriptions/{id}/review` | Save draft corrections | Persists user edits without activating schedules |
| `POST` | `/api/v1/prescriptions/{id}/confirm` | User confirmation | Requires explicit verification certification; activates schedules |
| `GET` | `/api/v1/prescriptions/{id}/document` | Authenticated stream | Strictly private file stream; blocks cross-user access (403) |
